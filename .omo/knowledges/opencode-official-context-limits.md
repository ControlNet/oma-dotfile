# OpenCode V1 official OpenAI model limits

- On OpenCode 1.18.32, `provider.codex.models.*.limit` in the repository applies only to the custom `codex` provider. OAuth models under the built-in `openai` provider use models.dev metadata plus the bundled Codex auth plugin's model overrides. The custom-provider limits are not copied to `openai` by `pull.py --oauth`.
- On 2026-09-23, `opencode models openai --verbose` reported `context/input/output`: `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`, and `gpt-5.4`: `1050000/922000/128000`; `gpt-5.4-mini`, `gpt-5.5`, and `gpt-5.6-sol`: `400000/272000/128000`. These are OpenCode's effective metadata, not a direct test of the upstream API's actual account limit. The bundled plugin explicitly sets `gpt-5.5` and `gpt-5.6` to `400000/272000/128000` for OAuth.
- A per-model override can be placed under `provider.openai.models.<model-id>.limit` in OpenCode V1 config. Use `context`, `input`, and `output` together when reducing a limit, so the metadata is internally consistent. A read-only trial using `OPENCODE_CONFIG_CONTENT` set `gpt-6-sol` and `gpt-5.5` to `272000/144000/128000`, and `opencode models openai --verbose` reported those values. An override changes OpenCode's local accounting and compaction behavior; it cannot increase the model/backend's true capacity.
- OpenAI's GPT-6 Sol and Luna model pages say prompts above 272K input tokens are charged at 2x input and cache rates and 1.5x output for the full request. The repository sets each model's local limit to `context: 400000`, `input: 272000`, `output: 128000` on both the built-in `openai` OAuth provider and the custom `codex` gateway. The official provider also exposes `gpt-6-sol-fast` and `gpt-6-luna-fast` aliases for the same base model IDs, so they receive the same limits. On OpenCode V1.18.32, `session/overflow.ts` uses `limit.input` minus its default 20K reserved buffer for automatic compaction when `input` is present. This is an estimated compaction trigger, not a strict per-request input-token guard; a large new prompt or another request path can still exceed 272K. Runtime inspection with `OPENCODE_CONFIG_CONTENT` confirmed both providers resolve Sol and Luna to the configured values while Astra remains at the catalog limit.
- OMP's custom-model schema has `contextWindow` and `maxTokens` but no separate input limit. Its Sol and Luna entries therefore retain `contextWindow: 272000` and `maxTokens: 128000` as a conservative total context budget, rather than mirroring OpenCode's 400K context.
- The repository installer removes the source `provider.codex` object in OAuth mode, but preserves existing installed `codex` settings and leaves any source `provider.openai` block intact. A local-only edit to `~/.config/opencode/opencode.jsonc` will be replaced by a later installer run, so persistent overrides belong in the repository template or in a separate higher-precedence config.
