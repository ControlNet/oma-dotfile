# OMO 5.0.0-beta.84 configuration audit

- `oh-my-openagent@beta` resolves to `5.0.0-beta.84` on 2026-09-23. The installed package and its OpenCode schema still accept `[opencode].agents.metis` and `.momus`; their runtime agents use the configured `high` and `xhigh` variants. The unified core documentation's `plan-consultant` and `plan-reviewer` rename applies to shared/core agents, not these OpenCode-specific keys.
- Beta.84 splits the former `deep` category into `deep-low` and `deep-high`. Its migration rewrote the installed `~/.omo/omo.jsonc` entry from `deep` to `deep-low`. Keep the source template canonical to avoid a fresh rewrite after each installer run. Configure both categories with the repository's chosen `gpt-6-sol` high tier; without `deep-high` override, the new built-in default uses `gpt-6-astra` high.
- The beta.84 OpenCode runtime applies the configured model to Prometheus and Sisyphus-Junior, but `opencode debug agent` shows no `variant` for either despite `reasoning: high`. A temporary project config using deprecated `variant: high` was migrated to `reasoning: high` on startup, and neither generated agent gained a variant. This is an upstream handling gap, not a template syntax error. Other configured agents returned the expected variants.
